1. Текст задания

Реализовать информационную систему, которая позволяет взаимодействовать с объектами класса Organization, описание которого приведено ниже:

Разработанная система должна удовлетворять следующим требованиям:

  • Основное назначение информационной системы — управление объектами, созданными на основе заданного в варианте класса.
  • Необходимо, чтобы с помощью системы можно было выполнить следующие операции с объектами: создание нового объекта, получение информации об объекте по ИД, обновление объекта (модификация его атрибутов), удаление объекта. Операции должны осуществляться в отдельных окнах (интерфейсах) приложения. При получении информации об объекте класса должна также выводиться информация о связанных с ним объектах.
  • При создании объекта класса необходимо дать пользователю возможность связать новый объект с объектами вспомогательных классов, которые могут быть связаны с созданным объектом и уже есть в системе.
  • Выполнение операций по управлению объектами должно осуществляться на серверной части (не на клиенте), изменения должны синхронизироваться с базой данных.
  • На главном экране системы должен выводиться список текущих объектов в виде таблицы (каждый атрибут объекта — отдельная колонка в таблице). При отображении таблицы должна использоваться пагинация (если все объекты не помещаются на одном экране).
  • Нужно обеспечить возможность фильтровать/сортировать строки таблицы, которые показывают объекты (по значениям любой из строковых колонок). Фильтрация элементов должна производиться только по полному совпадению.
  • Переход к обновлению (модификации) объекта должен быть возможен из таблицы с общим списком объектов и из области с визуализацией объекта (при ее реализации).
  • При добавлении/удалении/изменении объекта, он должен автоматически появиться/исчезнуть/измениться в интерфейсах у других пользователей, авторизованных в системе.
  • Если при удалении объекта с ним связан другой объект, связанные объекты должны удаляться.
  • Пользователи должны иметь возможность просмотра всех объектов. Для модификации объекта должно открываться отдельное диалоговое окно. При вводе некорректных значений в поля объекта должны появляться информативные сообщения о соответствующих ошибках.

В системе должен быть реализован отдельный пользовательский интерфейс для выполнения специальных операций над объектами:

  • Вернуть количество объектов, значение поля type которых равно заданному.
  • Вернуть количество объектов, значение поля fullName которых больше заданного.
  • Вернуть массив объектов, значение поля type которых меньше заданного.
  • Добавить нового сотрудника в организацию с указанным id.
  • Реализовать поглощение одной организацией другой без увольнения сотрудников.

Представленные операции должны быть реализованы в качестве функций БД, которые необходимо вызывать из уровня бизнес-логики приложения.

Особенности хранения объектов, которые должны быть реализованы в системе:

  • Организовать хранение данных об объектах в реляционной СУБД (PostgreSQL). Каждый объект, с которым работает ИС, должен быть сохранен в базе данных.
  • Все требования к полям класса (указанные в виде комментариев к описанию классов) должны быть выполнены на уровне ORM и БД.
  • Для генерации поля id использовать средства базы данных.
  • Для подключения к БД на кафедральном сервере использовать хост pg, имя базы данных — studs, имя пользователя/пароль совпадают с таковыми для подключения к серверу.

При создании системы нужно учитывать следующие особенности организации взаимодействия с пользователем:

  • Система должна реагировать на некорректный пользовательский ввод, ограничивая ввод недопустимых значений и информируя пользователей о причине ошибки.
  • Переходы между различными логически обособленными частями системы должны осуществляться с помощью меню.
  • При добавлении/удалении/изменении объекта, он должен автоматически появиться/исчезнуть/измениться на области у всех других клиентов.

При разработке ИС должны учитываться следующие требования:

  • В качестве основы для реализации ИС необходимо использовать Spring MVC.
  • Для создания уровня хранения необходимо использовать Hibernate.
  • Разные уровни приложения должны быть отделены друг от друга, разные логические части ИС должны находиться в отдельных компонентах.

2. UML-диаграммы

Серверная часть написана на Java 17 с использованием Spring Boot 3.5 (Spring MVC, Spring WebSocket) и Hibernate 6 (через Spring Data JPA), данные хранятся в PostgreSQL. Клиентская часть — набор HTML-страниц с JavaScript-модулями, которые раздаёт само приложение. Диаграммы построены в PlantUML, их исходные описания лежат в каталоге docs/uml репозитория. 2.1. Диаграмма пакетов

Приложение разделено на уровни: представление (web), бизнес-логика (service) и хранение (repository). Зависимости направлены только «сверху вниз»: контроллеры обращаются к сервисам, сервисы — к репозиториям, а сущности предметной области (domain) не зависят ни от одного уровня. Рассылка изменений клиентам вынесена в отдельный пакет realtime.

2.2. Диаграммы классов

Доменная модель

Координаты и адреса хранятся в отдельных таблицах и связаны с организацией ассоциациями «многие к одному», поэтому новую организацию можно привязать к уже существующим координатам и адресам. Ограничения из задания показаны на диаграмме в фигурных скобках. Они продублированы аннотациями Bean Validation и JPA в сущностях и ограничениями NOT NULL и CHECK в таблицах БД. Идентификаторы генерирует PostgreSQL (GENERATED ALWAYS AS IDENTITY), дата создания заполняется перед сохранением в методе onCreate() (@PrePersist).

Объекты передачи данных

Связанный объект в запросе передаётся одним из двух способов: идентификатором уже существующего объекта (id) или значениями полей для создания нового. Для адресов значение null означает, что адреса нет. Поле usages показывает, сколько организаций ссылается на координаты или адрес; оно заполняется только в списках вспомогательных объектов.

Уровень представления

Контроллеры только принимают HTTP-запросы и передают их сервисам, все операции выполняются на сервере. ApiExceptionHandler переводит исключения (ошибки валидации, некорректный JSON, нарушение ограничений БД, ошибки из функций БД) в ответ с общим сообщением и сообщениями по каждому полю формы.

Уровень бизнес-логики

Каждый публичный метод сервиса выполняется в транзакции. OrganizationService до сохранения проверяет все поля и ссылки на существующие координаты и адреса, поэтому новые вспомогательные объекты попадают в БД только при корректном запросе. CascadeDeleter собирает правила удаления в одном месте: вместе с организацией удаляются её координаты и адреса, если на них больше никто не ссылается.

Уровень хранения

Репозитории Spring Data JPA работают через Hibernate. Фильтрация таблицы по полному совпадению строится через Criteria API (OrganizationSpecifications), а пагинация и сортировка выполняются запросом к БД. Специальные операции вызываются только из SpecialOperationsRepository нативными запросами к функциям PL/pgSQL.

Оповещение клиентов об изменениях

Сервис публикует EntityChangedEvent внутри транзакции, а ChangeBroadcaster обрабатывает его с помощью @TransactionalEventListener(phase = AFTER_COMMIT): сообщение уходит всем подключённым клиентам только после фиксации транзакции, а откатившиеся изменения не рассылаются. Получив событие, клиент заново запрашивает данные и обновляет таблицу, страницу объекта или открытое окно изменения.

Клиентская часть

Каждой странице соответствует отдельный модуль из каталога pages. Общие части вынесены в модули: меню и уведомления (layout.js), форма организации с проверкой ввода (OrganizationForm), модальные окна изменения и подтверждения удаления (dialogs.js), REST-клиент (api.js) и подписка на изменения по WebSocket с автоматическим переподключением (realtime.js).

4. Выводы

В ходе лабораторной работы разработана информационная система для управления объектами класса Organization и связанными с ними объектами Coordinates и Address. Серверная часть построена на Spring MVC, уровень хранения — на Hibernate, данные хранятся в PostgreSQL. Приложение разделено на уровни представления, бизнес-логики и хранения; рассылка изменений вынесена в отдельный компонент.

Все операции над объектами выполняются на сервере в транзакциях. Координаты и адреса хранятся в отдельных таблицах, поэтому при создании организации её можно связать с уже существующими вспомогательными объектами. Требования к полям класса выполнены дважды: аннотациями Bean Validation и JPA на уровне ORM и ограничениями NOT NULL и CHECK на уровне БД. Идентификаторы генерирует PostgreSQL. Схему БД создают миграции Flyway, а Hibernate при запуске только сверяет с ней маппинг сущностей, поэтому расхождение кода и базы обнаруживается сразу.

Специальные операции реализованы функциями PL/pgSQL и вызываются из уровня бизнес-логики. Порядок значений перечисления для операции «type меньше заданного» совпадает с порядком объявления enum в Java. Значения fullName сравниваются побайтово (COLLATE "C"), чтобы результат не зависел от локали сервера БД. При поглощении обе организации блокируются (SELECT … FOR UPDATE) в фиксированном порядке, чтобы параллельные поглощения не приводили к взаимоблокировке.

Изменения доставляются всем клиентам по WebSocket. Событие рассылается только после фиксации транзакции, поэтому клиент, перезапросив данные, видит уже сохранённое состояние, а изменения из откатившихся транзакций до клиентов не доходят. Если объект изменили или удалили, пока у пользователя открыто окно его изменения, система предупреждает об этом.

В процессе работы пришлось учесть несколько неочевидных моментов:

  • в PostgreSQL значение NaN считается больше любого числа, а Infinity проходит проверку «больше 0», поэтому ограничения для координат и рейтинга дополнены явными проверками на конечность;
  • одни и те же координаты или адрес могут использоваться несколькими организациями, поэтому при удалении организации связанные объекты удаляются только тогда, когда на них больше никто не ссылается, а удаление самих координат или адреса каскадно удаляет все ссылающиеся на них организации;
  • по той же причине изменение координат или адреса в форме создаёт новый объект, а не меняет общий, иначе правка одной организации незаметно затронула бы другие.

В результате выполнения работы получен практический опыт проектирования многоуровневого веб-приложения на Spring, отображения объектной модели на реляционную с помощью Hibernate, переноса бизнес-операций в хранимые функции СУБД и синхронизации состояния между несколькими клиентами в реальном времени.

$$
DECLARE
    v_count BIGINT;
BEGIN

    SET employees_count = employees_count + 1
    WHERE id = p_organization_id
    RETURNING employees_count INTO v_count;

-- 5. Поглощение: все сотрудники (и годовой оборот) поглощаемой организации переходят
--    к поглощающей, поглощаемая организация удаляется. Возвращает новое число сотрудников.
CREATE OR REPLACE FUNCTION absorb_organization(p_absorber_id BIGINT, p_absorbed_id BIGINT)
    RETURNS BIGINT
    LANGUAGE plpgsql
AS
$$
DECLARE
    v_absorbed organization%ROWTYPE;
    v_count    BIGINT;
BEGIN
    IF p_absorber_id = p_absorbed_id THEN
        RAISE EXCEPTION 'Организация не может поглотить саму себя' USING ERRCODE = '22023';
    END IF;

    -- Блокируем обе строки в одном порядке, чтобы параллельные поглощения не взаимоблокировались
    PERFORM 1 FROM organization WHERE id IN (p_absorber_id, p_absorbed_id) ORDER BY id FOR UPDATE;

    SELECT * INTO v_absorbed FROM organization WHERE id = p_absorbed_id;
    IF NOT FOUND THEN
        RAISE EXCEPTION 'Поглощаемая организация с id = % не найдена', p_absorbed_id USING ERRCODE = 'P0002';
    END IF;

    UPDATE organization
    SET employees_count = employees_count + v_absorbed.employees_count,
        annual_turnover = CASE
                              WHEN annual_turnover IS NULL AND v_absorbed.annual_turnover IS NULL THEN NULL
                              ELSE coalesce(annual_turnover, 0) + coalesce(v_absorbed.annual_turnover, 0)
            END
    WHERE id = p_absorber_id
    RETURNING employees_count INTO v_count;

    IF NOT FOUND THEN
        RAISE EXCEPTION 'Поглощающая организация с id = % не найдена', p_absorber_id USING ERRCODE = 'P0002';
    END IF;

    DELETE FROM organization WHERE id = p_absorbed_id;
    RETURN v_count;
END;
$$;

 * удаляются, если на них больше не ссылается ни одна организация: общий адрес
 * другой организации при этом не пропадает.
 */
@Component
@Transactional(propagation = Propagation.MANDATORY)
public class CascadeDeleter {

    private final OrganizationRepository organizationRepository;
    private final CoordinatesRepository coordinatesRepository;
    private final AddressRepository addressRepository;
    private final ChangePublisher changePublisher;

    public CascadeDeleter(OrganizationRepository organizationRepository,
                          CoordinatesRepository coordinatesRepository,
                          AddressRepository addressRepository,
                          ChangePublisher changePublisher) {
        this.organizationRepository = organizationRepository;
        this.coordinatesRepository = coordinatesRepository;
        this.addressRepository = addressRepository;
        this.changePublisher = changePublisher;
    }

    public void deleteOrganizations(Collection<Organization> organizations) {
        if (organizations.isEmpty()) {
            return;
        }
        Set<Long> coordinatesIds = new LinkedHashSet<>();
        Set<Long> addressIds = new LinkedHashSet<>();
        List<Long> organizationIds = organizations.stream().map(Organization::getId).toList();
        for (Organization organization : organizations) {
            // getId() у ленивого прокси не инициализирует его
            coordinatesIds.add(organization.getCoordinates().getId());
            if (organization.getOfficialAddress() != null) {
                addressIds.add(organization.getOfficialAddress().getId());
            }
            if (organization.getPostalAddress() != null) {
                addressIds.add(organization.getPostalAddress().getId());
            }
        }

        organizationRepository.deleteAll(organizations);
        organizationRepository.flush();
        changePublisher.publish(Entity.ORGANIZATION, Change.DELETED, organizationIds);

        deleteUnusedRelatedObjects(coordinatesIds, addressIds);
    }

    /** Удаляет из переданных координат и адресов те, что больше никем не используются. */
    public void deleteUnusedRelatedObjects(Collection<Long> coordinatesIds, Collection<Long> addressIds) {
        List<Long> coordinatesCandidates = coordinatesIds.stream().filter(Objects::nonNull).distinct().toList();
        if (!coordinatesCandidates.isEmpty()) {
            List<Long> unused = coordinatesRepository.findUnusedIds(coordinatesCandidates);
            if (!unused.isEmpty()) {
                coordinatesRepository.deleteAllByIdInBatch(unused);
                changePublisher.publish(Entity.COORDINATES, Change.DELETED, unused);
            }
        }

        List<Long> addressCandidates = addressIds.stream().filter(Objects::nonNull).distinct().toList();
        if (!addressCandidates.isEmpty()) {
            List<Long> unused = addressRepository.findUnusedIds(addressCandidates);
            if (!unused.isEmpty()) {
                addressRepository.deleteAllByIdInBatch(unused);
                changePublisher.publish(Entity.ADDRESS, Change.DELETED, unused);
            }
        }
    }

import java.io.IOException;
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

/** Держит открытые соединения браузеров и рассылает им уведомления об изменениях. */
@Component
public class UpdatesWebSocketHandler extends TextWebSocketHandler {

    private static final Logger log = LoggerFactory.getLogger(UpdatesWebSocketHandler.class);
    private static final int SEND_TIME_LIMIT_MS = 5_000;
    private static final int BUFFER_SIZE_LIMIT = 512 * 1024;

    private final Map<String, WebSocketSession> sessions = new ConcurrentHashMap<>();

    @Override
    public void afterConnectionEstablished(WebSocketSession session) {
        // Декоратор сериализует отправку: WebSocketSession не потокобезопасен
        sessions.put(session.getId(),
                new ConcurrentWebSocketSessionDecorator(session, SEND_TIME_LIMIT_MS, BUFFER_SIZE_LIMIT));
    }

    @Override
    public void afterConnectionClosed(WebSocketSession session, CloseStatus status) {
        sessions.remove(session.getId());
    }

    @Override
    public void handleTransportError(WebSocketSession session, Throwable exception) {
        sessions.remove(session.getId());
    }

    public void broadcast(String payload) {
        TextMessage message = new TextMessage(payload);
        sessions.values().forEach(session -> {
            try {
                if (session.isOpen()) {
                    session.sendMessage(message);
                }
            } catch (IOException | IllegalStateException e) {
                log.debug("Не удалось отправить уведомление в сессию {}: {}", session.getId(), e.getMessage());
                sessions.remove(session.getId());
            }
        });
    }
}

export class ApiError extends Error {
    constructor(status, message, fieldErrors = {}) {
        super(message);
        this.status = status;
        this.fieldErrors = fieldErrors;
    }

async function request(method, url, body) {
    const options = {method, headers: {Accept: 'application/json'}};
    if (body !== undefined) {
        options.headers['Content-Type'] = 'application/json';
        options.body = JSON.stringify(body);
    }

    let response;
    try {
        response = await fetch(url, options);
    } catch {
        throw new ApiError(0, 'Сервер недоступен. Проверьте подключение и повторите попытку.');
    }

    const text = await response.text();
    let data = null;
    if (text) {
        try {
            data = JSON.parse(text);
        } catch {
            data = null;
        }
    }
    if (!response.ok) {
        throw new ApiError(response.status, data?.message || `Ошибка сервера (${response.status})`,
            data?.fieldErrors || {});
    }
    return data;
}

/** @param keepEmpty передавать пустые строки (фильтр «значение равно пустой строке») */
function query(params, keepEmpty = false) {
    const search = new URLSearchParams();
    for (const [key, value] of Object.entries(params)) {
        if (value !== undefined && value !== null && (keepEmpty || value !== '')) {
            search.set(key, value);
        }
    }
    const s = search.toString();
    return s ? `?${s}` : '';
}

export function h(tag, props = {}, ...children) {
    const el = document.createElement(tag);
    for (const [key, value] of Object.entries(props || {})) {
        if (value === undefined || value === null || value === false) {
            continue;
        }
        if (key === 'class') {
            el.className = value;
        } else if (key === 'dataset') {
            Object.assign(el.dataset, value);
        } else if (key.startsWith('on') && typeof value === 'function') {
            el.addEventListener(key.slice(2).toLowerCase(), value);
        } else if (key === 'value' || key === 'checked' || key === 'disabled' || key === 'selected') {
            el[key] = value;
        } else {
            el.setAttribute(key, value === true ? '' : value);
        }
    }
    append(el, children);
    return el;
}

    for (const child of children.flat(Infinity)) {
        if (child === undefined || child === null || child === false) {
            continue;

        el.append(child instanceof Node ? child : String(child));
    }
}

 * При попытке ввода такого символа рядом с полем на секунду появляется подсказка.
 */
export function numberInput(kind, onRejected) {
    const disallowed = kind === 'integer' ? /[^\d+-]/g : /[^\d.,eE+-]/g;
    const input = h('input', {
        type: 'text',
        inputmode: kind === 'integer' ? 'numeric' : 'decimal',
        autocomplete: 'off',
        maxlength: 40,
    });
    input.addEventListener('input', () => {
        const {value} = input;
        const cleaned = value.replace(disallowed, '');
        if (cleaned !== value) {
            const caret = value.slice(0, input.selectionStart ?? value.length).replace(disallowed, '').length;
            input.value = cleaned;
            input.setSelectionRange(caret, caret);
            onRejected?.(kind === 'integer'
                ? 'Можно вводить только цифры'
                : 'Можно вводить только цифры, знак, точку или запятую');
        }
    });
    return input;
}

// Событие: {entity: 'ORGANIZATION'|'COORDINATES'|'ADDRESS', change: 'CREATED'|'UPDATED'|'DELETED', ids: [...]}.
// После переподключения приходит {entity: '*', change: 'RESYNC'}: пока связи не было, события могли потеряться.

const listeners = new Set();
let socket = null;
let attempt = 0;
let everConnected = false;

export function onChange(listener) {
    listeners.add(listener);
    connect();
    return () => listeners.delete(listener);
}

function emit(event) {
    for (const listener of [...listeners]) {
        try {
            listener(event);
        } catch (e) {
            console.error('Ошибка обработчика обновлений', e);
        }
    }
}

function setStatus(online) {
    document.dispatchEvent(new CustomEvent('live-status', {detail: {online}}));
}

function connect() {
    if (socket) {
        return;
    }
    const url = new URL('ws/updates', location.href);
    url.protocol = location.protocol === 'https:' ? 'wss:' : 'ws:';
    socket = new WebSocket(url);

    socket.addEventListener('open', () => {
        setStatus(true);
        if (everConnected) {
            emit({entity: '*', change: 'RESYNC', ids: []});
        }
        everConnected = true;
        attempt = 0;
    });
    socket.addEventListener('message', (message) => {
        try {
            emit(JSON.parse(message.data));
        } catch (e) {
            console.error('Некорректное сообщение об изменении', e);
        }
    });
    socket.addEventListener('close', () => {
        setStatus(false);
        socket = null;
        const delay = Math.min(10_000, 500 * 2 ** attempt++);
        setTimeout(connect, delay);
    });
}

/** Склеивает пачку событий в один вызов (например, удаление адреса удаляет несколько организаций). */
export function debounce(fn, ms = 150) {
    let timer = null;
    return (...args) => {
        clearTimeout(timer);
        timer = setTimeout(() => fn(...args), ms);
    };
